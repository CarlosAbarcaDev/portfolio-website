## Platform

## Users

Primary audience is a mix of two visitors doing the same job: deciding whether to contact Carlos Abarca for a senior front-end / full-stack opportunity.

- Recruiters and hiring managers screening candidates for Senior Front-End / Full Stack roles, scanning quickly for evidence of real experience.
- Technical profiles (tech leads, engineering teams) verifying depth: stack, architecture, shipped systems, and whether claims hold up under inspection.
- Secondary audience: potential freelance clients evaluating delivery capability.

Both are evaluating one person, not a company. The site must win the recruiter in seconds and survive technical scrutiny.

## Product Purpose

Personal portfolio that proves ~7 years of programming and ~4 years of full-stack work through documented, real, shipped systems instead of a skills list. Success is defined by two outcomes: interview requests for full-stack roles (remote or with relocation) and freelance inquiries. The site exists to convert visitors into a contact: email, phone, LinkedIn, GitHub, or the portfolio domain.

## Capabilities and Constraints

- Confirmed site capabilities: responsive single page; scroll-aware nav active state; GSAP/ScrollTrigger + Lenis smooth scroll; project galleries capped at 6 screenshots per project; lightbox viewer with keyboard arrows, Esc, explicit close button, and swipe-to-close on touch.
- Stack: React 19 + TypeScript strict, Vite 8, Tailwind CSS v4, GSAP, Lenis. Build and lint: `npm run build` (tsc + vite + prerender script), `npm run lint` (oxlint). Node 22 (`.nvmrc`).
- Build output is prerendered: `scripts/prerender.mjs` renders the app to static markup inside `dist/index.html` (via Vite `ssrLoadModule` + `react-dom/server`), so crawlers and LLM agents that don't execute JS still receive the full content. `src/main.tsx` hydrates when prerendered markup exists.
- AI/search discoverability: JSON-LD (`Person` + `ProfilePage` + `WebSite`) in `index.html`, `public/llms.txt`, `public/robots.txt` (explicit AI-crawler allows), `public/sitemap.xml`, and a PNG OG image (`public/og-image.png`, generated by `scripts/generate-og.mjs` with sharp).
- Career positioning constraint (confirmed in project instructions, AGENTS.md): PHP/Laravel must NOT be presented as the core stack — Carlos does not claim seniority there; legacy PHP work in his GitHub exists but is out of scope. Currently leveling up Node.js + Express + TypeScript + MongoDB (learning project `devtree`).

## Product Principles

1. Evidence over claims — real shipped systems and their screenshots are the centerpiece; never fabricate testimonials, metrics, credentials, or deployments.
2. Two-audience clarity — recruiters must grasp value in seconds; technical reviewers must find enough depth to verify. Depth must not come at the cost of scanability.
3. Focused evidence scope — the three tourism systems stay the core proof; newer learning projects (Node.js) are acknowledged but must not dilute the current pitch.
4. Preserve the incumbent identity — refinements keep the established aesthetic, copy, structure, and bilingual tone; the presentation stays factual.
5. Contact is the conversion — every section should point toward an easy, obvious way to reach Carlos.
